WarmMemory for Agents

WarmMemory is a small in-process working-memory layer for agents. It keeps a fast buffer of recent or relevant interactions in RAM, so the agent does not need to search long-term memory or resend large transcripts on every turn.

Pandas-backed hot buffer Decorator-based capture Relevance-aware retrieval Benchmark harness included

What It Does

WarmMemory stores user and assistant turns in a small in-memory table.

  • recent(k) returns a classic sliding window.
  • relevant(query, k) ranks memory rows by importance.
  • retain_relevant(query, k) compacts the live working set.
  • @remember_interaction intercepts agent input and output automatically.

Why It Helps

It reduces latency by moving common retrieval work onto a cheaper hot path.

  • Less long-term retrieval on routine turns.
  • Smaller prompts because only top memory rows are sent.
  • Less repeated tool usage because recent state is retained nearby.
  • Cleaner memory hierarchy between hot and cold storage.

What It Is Not

This is not a claim of a brand-new foundational memory algorithm. It is an engineered architecture pattern plus a pluggable scoring interface.

  • The current scorer is a lightweight lexical heuristic.
  • The novelty is in the packaging of hot-memory management for agent loops.
  • You can replace the scorer with embeddings or a reranker later.

Latency Saving Path

Without WarmMemory, every turn often hits long-term retrieval and larger prompt assembly.

Step Without WarmMemory With WarmMemory
Lookup Search external memory every turn Check hot in-process buffer first
Prompt size Large transcript and retrieval bundle Only top relevant rows
LLM latency Higher input token load Lower token load on common turns
Fallback Always on expensive path Only used when warm memory is insufficient

How It Is Developed

The current project is built as a layered research prototype.

  • Storage layer: WarmMemoryBuffer stores interactions in a DataFrame.
  • Capture layer: remember_interaction automatically records agent turns.
  • Ranking layer: ImportanceScorer separates retrieval policy from storage.
  • Evaluation layer: the benchmark simulates workloads and scores tradeoffs.

This makes it easy to replace one piece at a time. For example, you can keep the buffer and swap only the scorer, or keep the scorer and replace Pandas with a production-oriented store.

Algorithm Status

The system is best described as a memory-management architecture, not a new mathematically novel algorithm in the strict research-paper sense.

Part Status Explanation
Sliding window memory Established pattern Keeping the last N items is common in streaming and conversation systems.
Relevance ranking Established pattern Ranking memory rows by query similarity is a standard IR idea.
Decorator-based capture Engineering design Useful implementation choice for agent frameworks, but not itself a new algorithm.
Warm-memory hierarchy for agents Potential project contribution The contribution is in combining hot memory, relevance retention, and fallback evaluation into one agent-oriented architecture.

If you want this to become a genuine algorithmic contribution, the next step is to define a new retention rule, adaptive scoring function, or learned policy that beats existing baselines on accuracy-latency tradeoffs.

Python Example

from warm_memory import WarmMemoryBuffer, remember_interaction

memory = WarmMemoryBuffer(capacity=8)

@remember_interaction(memory)
def agent(prompt: str) -> str:
    if "billing" in prompt.lower():
        return "Your invoice is available in the billing portal."
    return f"Echo: {prompt}"

agent("How do I reset my password?")
agent("Where is my billing invoice?")

recent_rows = memory.recent(4)
relevant_rows = memory.relevant("invoice", limit=2)
memory.retain_relevant("invoice", limit=4)

Benchmark Interpretation

In the current synthetic benchmark, recency is the fastest policy, while fallback is the most accurate. That is expected. A pure hot-path policy is cheaper, while a two-tier memory system recovers more facts by paying an occasional long-term retrieval cost.

The research question is not “which policy wins everywhere,” but “which policy gives the best accuracy-latency tradeoff for a target workload.”
